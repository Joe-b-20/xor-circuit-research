NOTATION: TWO DIFFERENT MEANINGS OF F MUST NOT BE CONFUSED
--------------------------------------------------------
The inherited local LP key is

  (h, y, F_T, orientation, q, z).

In the code this third entry retains the old name F.  It is the EE-gate
count of the NEXT canonical transpose, a reverse fan-out resource.  It is
NOT the number of full represented helpers.

For the new mathematics, use N3 for the number of actual helpers with
r_H=3 represented H--B incidences, and N2 for those with r_H=2.  Some early
proof prose called N3 'F'; that prose explicitly warns about this conflict.

The scalar state order is

  (a,b,Y,V,h_even,h_odd,l_even,l_odd,S_even,S_odd,budget).

Here a,b are the alternating OO counts; Y,V are the alternating EE counts;
h_even/h_odd are odd-helper counts.  The word 'even' here means the index
of the transpose iteration, not the parity of a signal.  The orientation
field identifies whether the even-indexed phase computes M or M^T.

EXACT NEW ROWS IN THE FINAL MODEL
--------------------------------
For a helper type (r,u,v), v is its degree in the H--H graph, which has z
edges and no loops.  Thus every actual helper has v<=z.  The original type
generator is retained unchanged, and the model appends the nonnegative
zero-bound row

  sum_(types with v>z) n_(r,u,v) <= 0.

This is a graph-realizability condition; even a loopless multigraph must
satisfy it.  It does not alone enforce the full simple-graph degree criteria.

Let C=20 for M and C=28 for M^T.  Let x=75-32-h-y in this fixed-G scan.
The independently reconstructed fixed-boundary geometry gives:

  3*N3 + q <= x+y,
  N2 + 5*N3 <= x+C.

The model also retains the valid integer roundings

  N3 <= min(C/2, floor((x+C)/5)),
  N3 <= floor((x+y-q)/3).

These are justified by actual represented gate incidences and ownership of
their chronological births.  They do not count merely possible boundary
decompositions and do not constrain any other intermediate masks.

For M^T with z=0, define

  A = sum_(r=3) u*n_(r,u,v),
  Z = sum (r-1)_+*u*n_(r,u,v),
  E = sum_(r=3) (u-2)_+*n_(r,u,v).

Set k_exc=2 when q<=6, and k_exc=1 when q>=7.  The final model adds

  A <= q-k_exc,
  Z+E <= 3*(q-k_exc).

An exceptional label has no r>=2 helper contact.  At least one such label
is necessary whenever z=0; at least two are necessary for q<=6.  The
inherited per-label excess/overflow proof charges only repeated-bright
labels, so the exceptional labels supply no capacity to Z+E.

For M^T at any z, let h0=sum_(r=0) n_(r,u,v), the number of helpers with
no represented H--B incidence.  The final model also adds

  A-h0 <= q-1,
  Z+E-3*h0 <= 3*(q-1).

When h0=0, triple pivots for all helpers make every H--H equation short
if no missing label is exceptional.  Together with the short H--B and
EE relations this would put 32 independent boundary rows inside R10,
whose dimension is 29.  Thus an exceptional label is required even when
z>0.  For h0>=1 the rows follow from the inherited A<=q and Z+E<=3*q.
These rows do not assume a stabilized transpose or a maximal EE count.

All inequalities from the inherited PROOF75 system remain in the model.
No solver-selected assumption or finite vocabulary for arbitrary signals
has been added.

EXACT CERTIFICATE FORMAT AND CHECKING
------------------------------------
For a fixed local key, the inherited plus new rows have the form

  A*n <= b,   n >= 0.

Each saved certificate is a vector of nonnegative INTEGERS lambda with

  lambda*A >= 0 coefficientwise,   lambda*b < 0.

Consequently 0 <= (lambda*A)*n <= lambda*b < 0, an exact contradiction.
The checker computes every coefficient and weighted right-hand side using
integer arithmetic.  The numerical optimizer only discovers multipliers.

The partial coverage checker reconstructs the scalar domain, verifies every
listed oriented state belongs to it, checks every q,z case below the claimed
s lower bounds, and checks that the bounds violate a scalar upper bound or
force the inherited positive two-step potential drift.
