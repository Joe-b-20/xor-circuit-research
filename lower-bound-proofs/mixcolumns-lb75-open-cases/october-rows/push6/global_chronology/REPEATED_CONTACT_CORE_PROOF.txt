EXACT SHARED-LABEL CONTACTS CONSUME THE REPEATED-HELPER CORE
2026-10-23

STATUS AND SCOPE

Three necessary inequalities hold for every normalized live binary XOR
circuit computing the standard AES bit matrix M or its transpose:

  N2 + 2*N3 + U_rep <= C + q,                              (1)
  2*N2 + 10*N3 + 3*U_rep <= 2*x + 2*C + 3*q,              (2)
  N2 + 5*N3 + 2*U_rep + A <= x + C + 3*q.                 (3)

Here C=20 for M and C=28 for M transpose.  N2/N3 count helpers with
exactly two/three ACTUAL represented H--B incidences; U_rep is the total
number of missing-label H--B incidences at these repeated helpers;
A is that count restricted to the full (r=3) helpers; q is the number
of missing even labels; x is the OO gate count.

Equation (1) uses a new complete exact-mask census and actual-birth
ownership.  Equations (2)-(3) also use the already audited per-color
weighted repeated-helper capacity at most three and at most one full
helper per color.  No arbitrary intermediate value is confined to a
finite candidate bank.  No fixed output-parent incidence, cancellation
restriction, depth bound, or prohibition on output reuse is imposed.

1. FIXED BOUNDARY AND THE COMPLETE REPEATED-HELPER CENSUS

The boundary B has 64 coordinates: 32 raw input units followed by the
32 required output masks.  Its 2,016 unordered pair XORs are distinct.
Enumerate all 41,664 unordered boundary triples and group them by XOR.
The maximum multiplicity is three.  Exactly 440 values for M, or 616
for M transpose, have at least two distinct triple expressions.  These
are all possible values of an actual helper with r>=2 represented
H--B incidences, because those actual incidences give distinct formal
helper-plus-boundary-triple equations.

Let O_* be the union of boundary output coordinates appearing in ALL
expressions of these repeated values.  It has C=20 or C=28 members.
Let B_* consist of the 32 raw input coordinates and O_*.

The new finite fact is:

  For any two DISTINCT repeated candidate values H,K, if
  H+K=B_i+B_j for a boundary pair, then i,j BOTH belong to B_*.

The verifier checks all 96,580 candidate pairs for M and all 189,420
for M transpose.  Of these, 11,520 and 16,992 respectively have a
boundary-pair difference.  Every one satisfies the displayed fact.
Pairs that cannot coexist in a circuit are included, enlarging the
tested universe.  All three expressions of a multiplicity-three
candidate are included even if its actual r is only two.  Thus no
actual choice of the two represented relations is omitted.

The complete census is regenerated by repeated_contact_core.py from
AES byte arithmetic.  It imports no helper-value tables or prior
enumerator.  REPEATED_CONTACT_CORE_RESULTS.json records all repeated
values and their expressions, the fixed core, pair counts, and a hash
of the completely enumerated successful contact-pair table.

2. WHAT A SHARED MISSING LABEL FORCES

For a missing even label e, let m_e count its actual H--B incidences
at r>=2 helpers.  A given helper has at most one such incidence for e:
the helper value and e determine its boundary endpoint uniquely.

If m_e>=2, choose any two contacts H+B_i=e and K+B_j=e.
The normalized helper values are distinct, so the unique boundary
pair satisfies H+K=B_i+B_j.  The finite fact places both endpoints in
B_*.  Repeating this with one chosen contact and every other contact
shows that ALL m_e boundary endpoints lie in B_*.

This conclusion uses exact endpoint masks.  It does not follow from
parity alone, or from the number of leaves in separate output trees.

3. COUNT THE ACTUAL BIRTHS TOGETHER

Let E_rep=N2+2*N3 and R=2*N2+3*N3.  Select every represented H--B
gate of every r>=2 helper, and one actual B--B reference gate for
each distinct even label appearing in those incidences.  Let L be
the number of these labels.  There are R+L distinct selected gates.

Now, for each missing label with m_e>=2, select all its m_e repeated-
helper H--B gates too.  Let p2 be the number of such labels and let
U_multi=sum_(m_e>=2) m_e.  These extra gates are distinct from the
represented gates and from their B--B references, since their labels
are missing.  Distinct actual H--B incidences are distinct physical
gate equations.  The total selected gate count is therefore

  R+L+U_multi.

All noninput values in these selected equations lie among:

  N2+N3 repeated helpers;
  at most C fixed-core outputs;
  L represented reference even values;
  p2 additional missing even values.

No additional boundary output is introduced by a multi-contact
missing label, by section 2.  Thus there are at most

  N2+N3+C+L+p2

noninput values in the selected equations.  Each selected physical
gate has a distinct birth result among those values.  Consequently

  E_rep + U_multi - p2 <= C,

or equivalently the stronger nonaggregated inequality

  E_rep + sum_(m_e>=2)(m_e-1) <= C.                        (4)

Let p be the number of missing labels with any repeated-helper
contact.  Then U_rep-p=sum_(m_e>=2)(m_e-1), and p<=q.
Equation (1) follows immediately.  If E_rep=C, no missing even label
can touch two repeated helpers, regardless of its birth type.

4. THE SAME SELECTED SUBSYSTEM FORCES OO BIRTHS

The count above bounds the number of values in the selected subsystem
whose birth lies outside it by

  C-E_rep-(U_multi-p2).

Every EE-born even value among the L+p2 selected even values must
occupy an outside birth: every selected equation containing an even
value has two odd endpoints and can produce that value only by OO.
Therefore at least

  (L+p2) - [C-E_rep-U_multi+p2]
    = L+E_rep+U_multi-C

of these even values are OO-born.  This proves

  L+E_rep+U_multi <= x+C.                                 (5)

The push5 full-helper ownership audit proves L>=3*N3, retaining all
sharing involving r=2 helpers.  It remains to eliminate U_multi.

The inherited per-label weighted capacity gives

  m_e+f_e<=3,

where f_e is the number of full-helper contacts, with f_e in {0,1}.
Thus m_e<=3, and m_e<=2 if f_e=1.  For m_e>=2,
m_e >= (3/2)(m_e-1).  Summing and using p<=q gives

  U_multi >= (3/2)(U_rep-q).

Together with (5) and L>=3*N3 this proves (2), with integer
coefficients.  The inequality remains valid if U_rep-q is negative.

For every color, the same allowed (m_e,f_e) pairs satisfy

  m_e*1_(m_e>=2) >= 2*m_e-3+f_e.

Summing over all q missing colors yields

  U_multi >= 2*U_rep-3*q+A.

Substitution into (5) proves (3).  The two OO rows are complementary:
one prices three repeated r=2 contacts efficiently; the other keeps
the restriction caused by a full-helper contact at the same color.

5. THE EXPLICIT G=75 SURVIVOR IS EXCLUDED

The saved M type vector from the end of push5 was

  2*(0,3,0)+4*(2,1,0)+4*(3,0,0)+4*(3,1,0).

It has N2=4, N3=8, E_rep=20, U_rep=8, A=4, q=4, x=25.
Equation (1) demands 28<=24, which is false.  Equation (2) demands
112<=102, and equation (3) demands 64<=57, both false as well.

The underlying conflict is precise: all repeated-helper core output
births are already owned, but sharing four missing labels across
eight repeated-helper contacts demands four additional birth slots
in that same core.  Sharing does not make those physical births free.

This excludes the entire actual-incidence class of that type vector.
It is not by itself an exclusion of all G=75 circuits or all remaining
aggregate profiles.  A separate exact scalar coverage computation is
required for any further numerical lower-bound claim.

6. REPLAY AND VALIDATION

Run from the workspace/package root:

  python push6/global_chronology/repeated_contact_core.py

Only the standard library is needed.  The finite census is independent
of circuit controls.  As an additional implementation check, the
script replays all ten archived 88-gate programs and their canonical
transposes.  It regenerates actual odd-graph edges, represented and
missing labels, helper types, selected physical gates and their birth
results, and checks (1)-(5).  All twenty orientation checks pass.

The fixed-boundary evidence and actual-gate ownership argument are
separate from numerical optimization.  Any later LP infeasibility
must still receive an exact integer certificate before being used
as a profile exclusion.
