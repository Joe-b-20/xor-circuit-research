Giant / closure keys of hunt/plateaus.json: exact identity, sizes, corrected estimates
=====================================================================================
2026-11-07.  [M] = measured (exact computation), [E] = estimated (model / estimator output).
Read-only on the repo and on hunt/ and estimate/; every output is in this directory.

Files
  list.py      -> entries.json   the 18 non-product keys: seed state, chain, sample (step 1)
  resolve.py   -> resolve.jsonl, resolve.log, pl_<key>.json   (step 2: pes_lib.compress, see below)
  recheck.py   membership re-check of the unresolved seeds against everything resolved
               (original records kept in resolve.jsonl.orig)
  table.py     -> table.out      the per-entry table below + appendix with all 18 seed value sets
  reestimate.py -> reestimate.out, landing_table_corrected.txt   (step 3)

Method
  * The 18 keys = 16 "giant-<hash>" + 2 p-keyed "closure" keys.  All 18 had the same failure in
    hunt/plateaus.py: compress's factor phase hit time_limit=180 s, so the fallback closure was cut
    at 1 state (stored size 1, identity = seed only) [M].
  * Each seed was first tested for exact membership (any of the 4 byte rotations, Plateau.contains)
    in all 264 product plateaus of plateaus.json (212 sprint + 52 pre-sprint) and in every plateau
    resolved so far; only non-members were compressed:
    compress(sp, seed, verify_limit=20000 (as plateaus.py), closure_limit=300000, time_limit=900),
    sp = make_space("mc", None), one process under nice 12, one fan memo shared across seeds.
    Order: one seed per chain first, then the rest; no new compress after 5,400 s of wall time.
  * Canonical key = plateaus.py key_of (h64 of the min-over-rotations sorted value union), so a
    resolved key equal to a catalogue key IS the same plateau.
  * Why some take long: compress checks time only between factor groups, and these plateaus have
    one coupled factor with 3e3-7e4 local choices (each choice = one remove1 fan, ~0.04 s here);
    such a group is explored to the end, then any coupling restart re-runs the groups (10-17
    restarts seen).  Fans are only computed at neutral-reachable states, so #fans is a [M] lower
    bound on plateau size for a failed attempt.
  * Resolved products with size > 20,000 are "pairwise" verified (factor phase consistent, not every
    member fanned) -- the same standard plateaus.py applied to all large catalogue plateaus.

What changed  [E]
  Almost nothing.  Resolving the giants adds 3 new singleton plateaus and turns 7 "possible new
  plateaus" into repeat visits by the same chain (which carry no incidence information).  No giant
  is a cross-chain coincidence, so Q2 stays 3, Chao2 and D2 move by ~3 %, and alpha stays ~1.35
  [0.55, 3.3].  The review2 swing (alpha 1.35 -> 0.5) required 18 independent singletons of size
  ~1e7; the facts are: 10 of 18 resolved into 8 plateaus of 2.6e4-2.6e6 (3 new), and the remaining
  8 move alpha only within 1.1-1.45 for sizes 3e4-3e6.

3. The "plausibly 3e4-5e5 plateaus" statement
---------------------------------------------
That range came from the size-weighted HT at alpha 0.75-1.0 (79k-403k), with alpha 0.75-1.0 taken
from the small-plateau signature repeats (alpha_check), and it was flagged as conditional on the
excluded giants.  With the giants resolved it survives essentially unchanged: at alpha 0.75 / 1.0
the corrected HT gives 81,773 / 412,972 [E], and with the 8 unresolved giants as singletons of any
realistic size (3e4-3e6) 83,730-124,547 / 417,234-702,554 [E].  The upper end may stretch from
~4e5 to ~7e5 only if all 8 unresolved keys are distinct plateaus of ~3e6 states; the lower end
(3e4) is untouched, since it is set by the alpha 0.5 HT (22,867 [E]) and by D2 / Chao2, which the
giants barely move (no new cross-chain coincidence).  The catalogue-only alpha remains ~1.35
[0.55, 3.3] and therefore still does not constrain N by itself; the dependence on alpha (not on the
giants) is what makes the estimate uncertain.  The review2 caveat "conditional on excluding the
giants" can be dropped: "of order 1e5, plausibly 3e4-5e5 (up to ~7e5 if the 8 still-unresolved
giant keys are all distinct multi-million plateaus)".
