1. [BLOCKS the "disjoint trails / neighbourhoods do not meet" reading; the numbers themselves are right]
   The 8 cross-chain meetings are exactly what independent wandering predicts for a level of the size F12
   estimates, so the graph carries no information about connectivity.
   Evidence (nullmodel.py): 146 chains, 1,462 distinct-node incidences, 1,054,422 cross-chain incidence pairs.
   If chains wander independently and uniformly over N nodes, the expected number of nodes entered by >= 2 chains
   (exact, not the pairs/N approximation) is
        N = 1,454 (only what was seen): 387      N = 2,500 (F12 floor): 291      N = 7,300 (F12 D2): 127
        N = 2e4: 50     N = 5e4: 21 (P(<=8) = 0.001)     N = 1e5: 10.4 (P(<=8) = 0.29)     N = 1.6e5: 6.6
   Observed 8 -> N_eff(visits) ~ 1.3e5, i.e. the same quantity as F12's signature D2 (254k before the exact-key
   merges, 132k with them).  Hunt D at 2.4 h gives the same number out of sample (dnull.py): 38 chains, 731
   incidences, 256,199 pairs, 2 shared nodes -> N_eff ~ 1.3e5.  So "146 chains produced 139 components" is the
   sampling-sparsity consequence of F12, not a second fact.  Two readings fit the data equally: trails that are
   genuinely isolated, and one connected web sampled at 1,462 points out of ~1e5.  The v3 over-splitting pushes
   the same way: 3 of the 8 meetings were found only because the states were exactly catalogued (26 % of states
   are), so exact-level meetings are undercounted by some factor between 1 and ~2.3 (the split ratio on coupled
   plateaus) -- still consistent with N_eff >= ~3e4 after any such correction, and still uninformative on
   connectivity.
   Fix: (i) in F11 and UNDERSTANDING 4 replace "a set of disjoint chain trails, not a web" and "the neighbourhoods
   do not meet [measured]" by the null-model comparison (wording in finding 12); (ii) the test F11 lacks is a
   prediction of the meeting count from an independent N: at the end of hunt D, shared v3 nodes should equal
   cross-chain pairs / 1.3e5 within Poisson error (registered in finding 13).  Significantly fewer meetings than
   that would be the first evidence of genuine locality; significantly more, of hubs.
   Side consequence for F12: since N >= D2 for any visit distribution, the node-level data put the number of
   plateaus well above the 2,500 floor (D2 on 8 coincidences, Poisson 95 %: [67k, 306k] at the signature level;
   divide by up to ~2.3 for hidden merges -> >= ~3e4).  The floor quoted in F12/I.3 is far more conservative than
   the sprint's own data allow; the exact catalogue on all 1,869 states would make this rigorous.

C. F13  SCOPED SAT REFUTATIONS
======================================================================================================

9. [SURVIVED]  Soundness, re-derived from sat87.py.
   (a) Equivalence.  (=>) is immediate.  (<=): a split-closed V >= K u TARGETS with |V| <= |K| + m can be ordered
   K first (INPUTS u K is split-closed by itself, asserted by run_scopes before every instance), then V \ K in
   V's own order; each remaining value splits over elements that are inputs, in K, or earlier in V \ K.  With
   distinct = True the module docstring's "pad with duplicates" is NOT the argument that applies (duplicates are
   forbidden); the correct one, given in the REPORT, is fresh splits: if INPUTS u V u {0} were closed under XOR it
   would be a subspace containing all 32 unit vectors, size 2^32 > 120, so some a ^ b (a != b in INPUTS u V) is a
   new value, and padding to exactly |K| + m distinct values is always possible.  Allowing a new gate to equal an
   existing value would be harmless but is not needed; forbidding it loses no solution.
   (b) Operand order: first index < second index loses nothing (XOR is commutative, a != b).  Consecutive-gate
   break: if g_{j+1} does not use g_j (g_j has the largest index, so it could only be the second operand:
   b[j+1][w_j] false), require first-operand index f_j <= f_{j+1}.  Soundness: swapping an adjacent independent
   pair keeps a valid sequence; a swap performed only when f_j > f_{j+1} strictly decreases the sequence
   (f_1..f_m) in lexicographic order at position j with earlier positions unchanged (later gates' indices w_j <->
   w_{j+1} may change but are at later positions), so the process terminates at a sequence satisfying every
   clause.  The clause (b[j+1][w_j] or -c[j+1][u] or c[j][u]) for u < w_j encodes exactly f_j <= f_{j+1}.
   (c) What UNSAT at m = k - 1 proves: no XOR-2 circuit with <= 87 gates has a value set that contains the
   88 - k values of K.  Outputs in K need not be recomputed (they are present); outputs in W are not in K (all
   88 values distinct) so they must be new values; a circuit whose gate equals an input, the zero value, or a
   duplicate has a smaller distinct value set that is still split-closed and still contains K, so it is covered;
   XNOR/constant gates cannot help a linear map; depth, fan-out, wiring and order are unconstrained.
   Empirical (sattest.py): repo windows A:v=00001010, A:v=03010002, A:v=84840000 (k = 4) and C:byte1.half1
   (k = 4): m = k - 1 is UNSAT under all four (distinct, symbreak) combinations (0.06-1.8 s), so the pruning
   constraints are not the source of the UNSAT; m = k is SAT and decodes to a circuit that check_circuit accepts
   as 88 gates containing K with new values disjoint from K and the inputs.
