# Independent review: hidden operands for maximal-window events

Review of `directions/independent.md` and its application of `directions/JOINT.md`. This is a hand review, not formal verification. No SAT, enumeration, exact gate search, computer-driven case elimination, or numerical verification was used.

## Verdict

The hidden-operand theorem, its rank-defect version, the symbolic sharpness construction, and the displayed conditional class bounds are correct with the stated hypotheses. Shared nonlocal operands and interacting events are handled. The theorem supplies a genuine lower bound on hidden work, but only for selected event values with the required support and projection properties; it gives no additive multi-sheet bound without controlling overlap.

One edge case was identified in the MixColumns corollary as initially written: `ceil((t+1)/2)` applies for `t>0`, not `t=0`. For zero selected events the guaranteed hidden count is zero. The author corrected the corollary to require `1<=t<=4`. The author also defined the operand graph as a loopless multigraph, a useful precision for the more general local-partner-capacity variant. In the stated rank-defect result the retained pairwise-distinct projection hypothesis already forbids parallel edges, because two gates with the same operand pair would have equal values.

## Proof audit

Let `W` be a maximal clique that is also an output window, and let each selected event value have support exactly `W`.

* Every event cancels some block `q` outside `W`. Maximality yields a block `d` in `W` nonadjacent to `q`. Both operands carry `q`, and at least one carries `d`; that operand is nonlocal. The added singleton-window convention ensures it is a gate, not an input.
* Fix a nonlocal physical operand `a` and choose `q` in its support outside `W`. Again choose `d` in `W` nonadjacent to `q`. In any selected gate `f=a+b` with local partner `b`, cancellation of `q` requires `b` to carry `q`, so locality prevents `b` from carrying `d`. Consequently `pi_d(f)=pi_d(a)`. The selected values have pairwise-distinct `d`-projections, so at most one can use `a` with a local partner. This applies no matter how many other uses `a` has.
* For selected gates with two nonlocal operands, use one graph edge for each physical gate. An undirected cycle gives a nonzero coefficient vector of selected events whose output values sum to zero: every operand value occurs an even number of times. Thus independence forces a forest, with `m=h-c` nonlocal/nonlocal edges. The at most `h` local-partner events give `t<=2h-c`. Nodes in `A` used only by a local-partner event are isolated vertices and must be included in `h,c`.
* Without full independence, the graph's cycle space embeds injectively into the kernel of the linear map from selected-event coordinates to their values: the coefficient vector is unchanged on its distinct edge coordinates. Therefore `m-h+c<=t-r`, where `r` is the rank of all selected values. Together with the local-partner count this yields `t<=2h-c+(t-r)`, i.e. `r<=2h-c`. For the generalized `lambda` version, retain edge multiplicity when discussing cycle-space dimension; a repeated pair then forms a two-edge cycle. A self-loop would give zero event value and cannot occur when `W` is nonempty.

The selected events themselves need not be visible for this combinatorial argument. If the circuit computes the designated outputs and an operand is nonlocal, support can only grow along any continuation without a further event, so it cannot reach an output on such a continuation. Thus every nonlocal operand gate belongs to `Q` or `E\F`, whether it is itself a non-event or a hidden event. Selected visible events can interact elsewhere; that does not alter the direct-operand graph proof.

## Sharpness and MixColumns

In the proposed tree family, the only gates supported on the nonlocal pair of blocks `{B,C}` are the `h` gates `a_i`; each reaches every relevant selected output only through a selected event. The other gates are designated outputs or selected output events, so precisely those `h` are hidden. The selected events have the two required block supports. Their `B`- and `D`-projections are pairwise distinct. Every coefficient of `y_i` in a dependence vanishes by inspection of `z_i`; the tree-edge values left are independent by successively deleting a leaf. The graph is the specified tree, giving `t=2h-1=2h-c`, including the single-vertex case.

For each of sheets 1, 3, 4, 5, 6, 7, the recorded window is a maximal clique. The four own-block row projections `E_c` and each set of four other-block projections `s_c` are distinct. The `E_c` are independent because their matrix `I+J` satisfies `(I+J)^2=I` over `F_2`. Thus every nonempty subset of `t` selected output events in such a sheet forces at least `ceil((t+1)/2)` distinct hidden operand gates; for `t=0` the guarantee is zero. This remains valid with arbitrary other visible and hidden events.

For the special class in which those four output gates are the entire visible-event set, each has `J={j}`: its full support is the maximal window `W_j`, which is contained in no other distinct MixColumns window. The hidden theorem supplies `H>=3`, and the two-pair reconstruction supplies `Delta_83,Delta_84>=2`. The resulting calculations in the direction note are correct: sheet 1 gives 80 from the 83 form; sheet 3 gives 77 from the 84 form; sheets 4, 5, 6, 7 give 81 from the 84 form. The event-free charged-family and joint-local theorems remain dependencies of these numerical bounds. They are conditional class results and do not improve the published unrestricted lower bound of 75.

The same hidden gate may be an operand of selected outputs from different sheets, so the per-sheet lower bounds cannot be summed without a separate cross-sheet capacity argument. The sharp tree family shows the factor two cannot be improved solely from maximality, full-window support, blockwise-distinct projections, and independence.

## Follow-up: Theorem HR and revised one-sheet bounds

I independently reviewed the final `independent.md` after the componentwise separated-projection theorem was added. Theorem HR is correct under its stated same-maximal-window support hypothesis, without independence or blockwise-distinctness. No enumeration or code was used.

For each nonlocal/nonlocal event edge, the two endpoint values have equal projections outside `W` because their sum is supported on `W`. Equality propagates along the physical operand component. Its common outside projection `z_i` is nonzero, since a value supported inside `W` is local. For any block `q` in `z_i`, maximality of the window clique ensures some `d in W` is nonadjacent to `q`; consequently `D_i` is nonempty. Every local partner of a selected event assigned to the component has outside projection `z_i`, and so contains each such `q`; it must vanish on every incompatible `d`. Each selected event's `D_i`-projection is consequently one vertex projection or the sum of two. Therefore the span of those event projections has dimension at most the number of distinct physical component vertices. Components are disjoint, and their assigned events partition the selected gates, which proves the sum in HR. This argument is unaffected by parallel selected edges or dependencies among selected values.

On any own block the four MixColumns row projections `E_c` are independent. On any other window block the `s_c` are the four edges of a 4-cycle and have exactly one nonzero linear relation, the sum of all four. Therefore any proper subset of the rows is independent on every window block. Because every component has a nonempty separated block set, a component assigned `k<4` selected rows has projection rank `k`; one assigned all four has rank at least three. Summing over components gives the stated hidden-work profile `1,2,3,3` for `t=1,2,3,4`. When `t=4`, more than one component or a separated set containing the own block improves the bound to four, as stated.

For the specific profile where the full visible set consists of `t` output events from one listed maximal-window sheet, each pair of distinct own-block triple sums shares two input coordinates. Pairing them gives the stated `floor(t/2)` shared-piece improvement, while the component theorem supplies `h_t=(1,2,3,3)`. Substituting these into the 83/84 inequalities yields exactly the revised rows `82,82,81,80`; `82,81,79,77`; and `83,83,82,81`. The new `t=3` entries are correct. The reduced-circuit condition needed by the charged-chain inequalities is now explicit.
